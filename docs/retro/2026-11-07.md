# Retrospective: 2026-11-07 agent session

Session source: `2026-11-06T21:48:16.537Z_01a1b2d5-7718-7403-8a07-cbaf26d1858b.jsonl`.

The session ran 30 user turns and 254 tool calls. It used 230 Bash calls, 15 edits, 5 writes, 3 reads, and 1 subagent call. Fifteen calls failed or returned errors.

## Findings

### F1 — High: user-level write guard was not part of the repo's verification surface

The session found and changed `~/.pi/agent/extensions/write-guard.ts`, not a tracked repository file. The extension was the cause of the user's repeated confirmation prompts. The fix was checked with ad hoc `bun -e` scripts, but no persistent regression test exists and CI cannot see the file. The extension is globally loaded by pi, so its behavior affects every repo and every session, while this repo's `bun run check` cannot detect regressions.

The current extension has a small classifier and a Bash-write heuristic. Both are behavior-critical and currently have no durable test. Add a user-level test harness or move the guard into a tracked extension package with tests. Until then, every future edit requires a manual smoke check.

### F2 — Medium: the session spent many calls rediscovering batch documentation boundaries

The batch guide, agent-config guide, prompt-writing guide, and free-model guide were repeatedly inspected and compared by line ranges. The docs now contain pointers, but the top-level agent instructions only point at `docs/agent-config-guide.md`; they do not state that batch work starts at `docs/batch-guide.md` or that prompt craft is in `docs/prompt-writing.md`.

Add a single navigation pointer to `AGENTS.md`: use `docs/batch-guide.md` for `mypi-batch` changes and `docs/prompt-writing.md` for general prompt craft. Keep detailed content out of `AGENTS.md`.

### F3 — Medium: documentation drift was detected only by manual code comparison

The batch sweep found missing `retries.json`, stale record-tree wording, an omitted `supervisor-stalled` reason code, and a stale source line citation. `bun run check` passed before those docs were corrected because the existing guard checks links and citation symbol existence, not citation line accuracy or documentation coverage of emitted record files and reason codes.

Add deterministic checks for the batch guide's record tree and reason-code list. Do not add a prose linter that tries to understand every sentence. The code should expose the file names and codes from one authority, and the test should compare the documented list with that authority.

### F4 — Low: the session used temporary tests for the write-guard fix

The write-guard behavior was tested with inline `bun -e` scripts. This was fast and useful, but the scripts were deleted and cannot prevent regressions. This is a consequence of F1 and should not become a second framework.

## Existing guardrail status

The repository already has CI at `.github/workflows/check.yml:23` running `bun run check`. The package script runs lint, typecheck, unit/integration tests, and web tests. The repo therefore does not need a new general CI check.

`AGENTS.md` is short enough that no global-instruction split is justified from this session. Its strongest useful role remains navigation and repository policy. The detailed prompt-craft material belongs behind a pointer.
